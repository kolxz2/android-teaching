# Практика 08. Сохранение операций FinanceApp через Room

**База для работы:** принятая версия практики 7 в ветке `master` проекта FinanceApp.
**Результат:** история, баланс и число операций восстанавливаются после остановки приложения в эмуляторе.
**Формат:** отдельная веб-презентация курса. На 26 шагах показаны фрагменты кода для ручного ввода; копирование отключено, как в практике 7. Каждый шаг задаёт место изменения, действие, причину и проверку. Подробные пояснения находятся в заметках преподавателя.

## Порядок занятия

1. Воспроизвести потерю истории и создать ветку `lecture-08` от обновлённого `master` после принятия практики 7.
2. Подключить Room 2.8.5 и KSP 2.3.12 через каталог версий и Gradle.
3. По отдельности создать Entity, TypeConverter, DAO и RoomDatabase. Проверить сборку до изменения ViewModel.
4. Вынести чтение, запись и работу с фоновым потоком в `TransactionRepository`.
5. Добавить состояние загрузки и ошибки, затем связать репозиторий с ViewModel. Сохранить существующие `addTransaction` и `reduce`.
6. Обновить экран и строковые ресурсы.
7. Проверить сохранение через интерфейс эмулятора и посмотреть таблицу в Database Inspector. Команды `adb` и инструментальный тест в практику не входят.
8. Запустить проверки проекта, отправить ветку и открыть Pull Request в GitHub из `lecture-08` в `master`.

Теоретическая лекция 8 обсуждает также Room 3. В этой практике используются зависимости и API Room 2.8.5 из FinanceApp; не смешивайте пакеты двух версий.
